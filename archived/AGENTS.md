# AGENTS.md — OpenVibe monorepo

OpenVibe is a Node.js monorepo (npm workspaces) replacing the legacy
HoboStreamer/HoboApp runtimes with native services. Active phase tracking lives
in [PHASES.md](PHASES.md); architecture rules in [ARCHITECTURE.md](ARCHITECTURE.md);
phase notes under [context/](context/); product/runtime docs under
[docs/openvibe/](docs/openvibe/).

## Workspace layout

- [services/](services/) — native Express services (`openvibe-network`,
  `openvibe-events`, `openvibe-media`, `openvibe-live`, `openvibe-chat`,
  `openvibe-community`, `openvibe-billing`, `openvibe-content`,
  `openvibe-ai`, `openvibe-games`, `openvibe-realtime`, `openvibe-workers`,
  `openre-stream`).
- [packages/](packages/) — shared libs (`openvibe-contracts`, `openvibe-sdk`,
  `openvibe-runtime`, `openvibe-persistence`, `openvibe-queue`,
  `openvibe-realtime`, `openvibe-redis`, `openvibe-storage`,
  `openvibe-observability`, `openvibe-icons`).
- [scripts/](scripts/) — `run-tests.js`, `check-syntax.js`, readiness,
  cutover, dev stack, migration tooling.
- [deploy/](deploy/) — `compose/docker-compose.local.yml`, nginx, env examples.
- [data/](data/) — runtime + readiness reports (gitignored except checked-in
  reports under `data/readiness/` and `data/migrations/`).
- `compat/`, `HoboReposToMigrateFrom/` — legacy migration inputs only; never
  required at runtime.

## Build, check, test (always use these — no ad-hoc node/jest)

| Goal | Command |
|---|---|
| Syntax/lint over every JS file | `npm run check` |
| Full test suite (deterministic) | `npm test` |
| Faster parallel tests | `npm run test:fast` |
| Only changed components | `npm run test:changed` |
| One component | `npm test -- --component=openvibe-content` |
| One file | `npm test -- --file=services/<svc>/test/x.test.js` |
| List components | `npm run test:list:components` |

Full runner reference: [docs/openvibe/testing-workflows.md](docs/openvibe/testing-workflows.md).
**Do not pipe runs to `| tail` — it hides live progress; tail
`.cache/openvibe/test-runner/latest.log` instead.**

## Readiness + smoke

| Goal | Command | Notes |
|---|---|---|
| Offline production-readiness report | `npm run readiness` | Writes [data/readiness/openvibe-production-readiness-report.json](data/readiness/openvibe-production-readiness-report.json). Currently **yellow** by design. |
| Schema drift (sqlite vs postgres migrations) | `npm run readiness:schema-drift` | Must stay green. |
| Browser smoke (HTTP fixture) | `npm run smoke:browser` | Requires services on their ports. |
| Browser smoke (Playwright) | `npm run smoke:browser:playwright` | Requires Playwright + live stack. |

## Architecture rules (do not violate)

Read [ARCHITECTURE.md](ARCHITECTURE.md) before cross-service work. Key invariants:

1. **No cross-service DB writes.** Talk via `@openvibe/sdk` clients, registered
   capabilities, or the event bus (`@openvibe/sdk/events-client`).
2. **Identity is centralized** in `services/openvibe-network/server/identity.js`.
3. **Events, capabilities, contracts, user-modules carry `version`.** Always pass it.
4. **Legacy Hobo folders are migration/reference only.** Never proxy to or
   require a live `hobo.tools` / hobostreamer process from a default route.
5. **OpenVibe APIs are mounted on a single `apiRouter`** so each service is
   independently liftable.

## Persistence conventions (high-impact)

- Each service has `server/db.js` (SQLite via `better-sqlite3`) and parallel
  `server/migrations/postgres/NNN_*.sql` files. Both must stay in sync — the
  `readiness:schema-drift` check enforces this.
- The shared compat helper in `packages/openvibe-persistence/sql-compat.js`
  auto-injects `rowid BIGINT GENERATED BY DEFAULT AS IDENTITY UNIQUE` after
  every `CREATE TABLE`; for `id INTEGER PRIMARY KEY AUTOINCREMENT` it emits
  `id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY, rowid BIGINT
  GENERATED ALWAYS AS (id) STORED UNIQUE`. Postgres migrations must include
  matching `rowid` columns explicitly.
- Most services still bootstrap SQLite directly (see [docs/openvibe/persistence-cutover-plan.md](docs/openvibe/persistence-cutover-plan.md));
  `OPENVIBE_PERSISTENCE_MODE=postgres` is descriptor-only until adapters are
  wired per service.

## Local stack topology (when running `stack:local:*`)

- `COMPOSE_PROJECT_NAME=openvibe-local`. Start/stop scripts proactively clean
  the legacy `compose` project to avoid stale port conflicts.
- Billing: container port 5000 → **host port 5001**. Browser smoke and
  `deploy/nginx/conf.d/openvibe.conf` already target `127.0.0.1:5001`.
- Postgres/Redis are not published on host ports.
- Network host-routed assets: `attachIconAssets(...)` MUST be mounted before
  `attachHostRouter(...)` in
  [services/openvibe-network/server/index.js](services/openvibe-network/server/index.js)
  or `/assets/openvibe-icons.{js,css}` will be intercepted by the host router 404.

## Status truthfulness

Readiness/smoke reports are intentionally honest: gates are `green/yellow/red`
based on real probes. **Do not flip a gate to green by silencing checks.** When
a slice is incomplete, mark it deferred (yellow) and document it in the
matching `context/PHASE_*.md` file plus [PHASES.md](PHASES.md).

## Editing pitfalls

- After adding columns/tables to a SQLite `SCHEMA_SQL` string, mirror the
  change in the matching `services/<svc>/server/migrations/postgres/*.sql`
  file or `readiness:schema-drift` will fail.
- `services/openvibe-content/server/db/` has separate `sqlite.js` and
  `postgres.js` — keep `getProductWorkflowStatus()` and friends in sync.
  `content_items` has no `kind` column (only `content_sources` does).
- New routes on a service must be added inside the function that builds its
  router (commonly `routes.js`) **before** the trailing `return r;`.
